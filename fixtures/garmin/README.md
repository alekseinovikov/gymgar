# Fixtures Garmin

Очищенные копии настоящих ответов Personal API. Репозиторий публичный, поэтому в нём лежат только результаты `cargo xtask scrub-*`; сами выгрузки остаются на машине автора (`temp/garmin-samples/`, в `.gitignore`) и в репозиторий не попадают никогда.

| Файл | Что это | Кто читает |
|---|---|---|
| `strength-plan.zip` | Файл настоящей силовой тренировки «FB2» (программа, которую часы вели по шагам): 31 активный подход, отдых между ними, 2925 точек пульса. Внутри один `activity.fit`. | `crates/garmin/tests/it/fit_fixture.rs`, дальше `sync` и `engine` |
| `activities-page.json` | Страница списка активностей (`GET /activitylist-service/activities/search/activities`): 8 активностей пяти типов (`strength_training`, `cycling`, `running`, `pilates`, `treadmill_running`). | дальше `sync::list` и `engine` |

## Откуда

Обе выгрузки сняты 2026-10-23 с аккаунта автора через Personal API: страница списка из 100 активностей и архив одной силовой тренировки (`GET /download-service/files/activity/{id}`, ZIP с одним `.fit`).

## Как очищены

Файл `.fit` строится заново, а не замазывается: что инструмент не знает, того в выходе нет. Список активностей очищается по списку запретов: известные личные поля удаляются, остальное остаётся как было.

- **`scrub-fit`** разбирает `.FIT` и пишет его снова тестовым писателем `gymgar-garmin` (`fit::testing::FitWriter`). В выходе только то, что читает приложение: программа (`workout`), шаги, заголовки упражнений, подходы (отдых тоже: в нём длительность отдыха) и пульс (только время и частота). Нет `device_info` и серийных номеров, `user_profile`, позиций GPS и любых сообщений, которых приложение не читает. Подход без времени начала получает начало активности, без длительности — 0 с (в настоящем файле таких нет). Файл в архиве называется `activity.fit`, а не `<id>_ACTIVITY.fit`.
- **`scrub-list`** берёт до `n` активностей разных типов (по одной каждого типа в порядке появления, потом по второй и так далее; порядок списка сохраняется) и:
  - удаляет все ключи `owner*` (id, имя, отображаемое имя и ссылки на картинки владельца), `userProfileId`, `activityUUID`, `deviceId`, `locationName`, `privacy`, `startTimeLocal` (рядом с `startTimeGMT` оно выдаёт часовой пояс; приложение читает только `startTimeGMT`) и любые координаты (`*Latitude`, `*Longitude`), а также все строки-ссылки на любой глубине;
  - заменяет `activityName` на `<typeKey> <номер в выходе>` (в настоящих названиях есть город и имя);
  - даёт активностям выдуманные `activityId` по порядку выхода: 1000001, 1000002 и так далее (`FIRST_SYNTHETIC_ID` в `xtask/src/scrub.rs`). Из настоящих id они не выводятся, поэтому настоящих id в фикстурах нет.

  В отличие от `scrub-fit`, это список запретов, а не разрешений: личное поле, которое Garmin добавит позже, останется в выходе, пока его не впишут в `scrub.rs`. Поэтому выход всё равно читают глазами (ниже), а тест `committed_activity_page_holds_nothing_personal` в `xtask` проверяет закоммиченную страницу: нет ключей `owner*`, `privacy`, `startTimeLocal`, `activityUUID`, `userProfileId`, `deviceId`, `locationName`, координат и ссылок, а все `activityId` меньше 10 000 000.

Что осталось и почему: время начала в UTC и показатели активностей (нужны для разбора и статистики), тексты заметок к шагам программы вроде «С канатом» (это текст программы, не личные данные), названия упражнений на языке часов.

## Как пересобрать

Нужны исходные выгрузки (есть только у автора):

```bash
cargo xtask scrub-fit <activity-id>.zip fixtures/garmin/strength-plan.zip
cargo xtask scrub-list activities.json fixtures/garmin/activities-page.json --take 8
```

Выбор детерминирован: те же входные файлы дают те же выходные.

## Перед коммитом новых fixtures

Выход читают глазами и проверяют поиском: ни в одном файле не должно быть имени и фамилии владельца, `owner`, `s3.amazonaws.com`, названий мест, UUID отображаемого имени и активности, настоящих id активностей, местного времени, любых ссылок и координат.

```bash
grep -n -i -E '<имя>|<фамилия>|<город>|<настоящий id>|owner|s3\.amazonaws|http|latitude|longitude|uuid|privacy|timelocal' fixtures/garmin/activities-page.json
```

Для `.fit` ту же роль играют тесты в `crates/garmin/tests/it/fit_fixture.rs` (в файле только разрешённые сообщения) и `scrub_fit_drops_device_and_profile` в `xtask`.
